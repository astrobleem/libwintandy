libwintandy - staged Windows3.0 adoption

UI: unchanged LTWUI implementation, public LWTANDY.H, TShell include/build-only
candidate. The24 host checks and exact expanded-source comparison pass. Native
clipping/hover/overlap/reopen/full-frame and CPU/RAM checks await an explicit
slot after CF/launcher and panning owners. Preserve completed display evidence.

Audio: exact pinned local R4 archive and all253source entries verified. Correct
RAWAPP name collision, retain guarded RAWSCORE for five raw utilities, route
MINIPLAY includes through LWAUDIO. Provider/IRQ bodies and event formats remain
unchanged. Host format126, transport1493, renderer10029 and live18 checks pass,
as do beat assertions and packed-layout/typed-include fixtures. Corrected
MINIPLAY old/direct versus facade includes have equal host expansion. These
are unsanitized host tests, not native timing/pixel/binary qualification.

Next: fresh MSC6 MINIPLAY/RAWQA/five raw ports builds, then same-fixture native
playback, pause/resume, stop/restart, EOF, owner contention, cleanup and GUI
comparisons with source/runtime pins. No new binaries ship before these gates.

Other apps: no broad migration. Existing nine R4 utility ports already share
providers but have not adopted this facade. MPLAYER conversion remains separate
and unfinished; Buddy needs exact versioned bridge and native checks. Pinball
is a later profiling candidate: it already caches static table, uses XOR moving
objects and suppresses erase. Its full WM_PAINT/table-area copies and sound
service need measurement before promising a library speedup. No Pinball edits.

PCjr UI is hardware-neutral; audio backend/admission and tests remain pending.
Future video/input extraction is design scope only. Windows3.1 is parked.
