libwintandy - build instructions

Host UI checks:
  python libtandywin/TESTS/RUN.PY
Host production format, MOD and RAWCLK checks:
  python libtandywin/AUDIO/HOST/RUNHOST.PY --out <new-output>
Host shared PSG/PIT ownership checks:
  python libtandywin/AUDIO/HOST/RUNRAW.PY --out <new-output>
Host layout and typed facade checks:
  python libtandywin/AUDIO/TESTS/FACADE/RUN.PY
Additional foreground scheduler checks:
  python libtandywin/AUDIO/HOST/RUN.PY --out <output>

On Windows these runners compile through:
  C:\Users\chad\Documents\Codex\toolchains\gcc-ucrt64.py
The launcher preflights the compiler and required DLLs before starting GCC.
Windows --cc may name only that launcher. Linux --cc selects a host compiler.
The tests exercise actual source with USER or hardware mocks; native Windows
execution uses the separate guarded builders below.

Win16 UI: use caller-supplied MSC6 and Windows3.0 headers/libraries.
  CL /nologo /c /G0 /Gw /AS /W3 /Od /I<owned-include> LTWUI.C
Link LTWUI.OBJ once with the caller, using the same memory model. Include
WINDOWS.H before LWTANDY.H.

Current native sound and RAWCLK builds use the OEMSound checkout:
  python src/win30/DRIVER/BUILD.PY --dosbox <DOSBox-X>
    --toolchain <owned-MSC6-DDK-root> --lease <shared-emulator-lock>
    --out <new-private-output>
  python experimental/WINLIB30/SOURCE/BLDRAW.PY --dosbox <DOSBox-X>
    --toolchain <owned-MSC6-DDK-root> --lease <shared-emulator-lock>
    --out <new-private-output>

The one sound provider builds as SOUND.DRV. The RAWCLK builder uses the same
current TIMECLK consumer source as libtandywin/AUDIO/SOURCE. Both builders
preflight external tools, acquire the shared emulator lease, inspect running
processes and run only a bounded owned child. Their receipts pin source and
runtime bytes. OEMSound tools/WINAMP generates the complete native DOS Setup
package. Retained earlier builders and receipts remain historical records.
